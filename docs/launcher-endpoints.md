# Launcher endpoints

Served to the JLoco Launcher (`JLoco-Client/launcher/`, `remoteBase` = `http://<host>/dofus/launcher`).
These URLs are a contract with already-installed launchers: keep the paths and JSON shapes.

| Path (under `public/launcher/`) | Purpose |
|---|---|
| `status.php` | `{"name":string,"login":bool,"game":bool,"players":int\|null}`: TCP probe of the login/game ports (`ServerStatus`) plus accounts currently logged in. |
| `news.php` | `[{"id","title","content","date","author","img"}]`, latest `website_timeline_news` rows (`?limit=`, max 30). Same table as the site's news, written from `/admin`. |
| `manifest.json` | Generated by `JLoco-Client/launcher/tools/build-manifest.js`. |
| `files/<relative/path>` | One copy of every client file, laid out exactly as in the client install tree. |

Layout:

```
JLoco-Web/public/launcher/
├─ status.php
├─ news.php
├─ manifest.json          <- from dist-update/
└─ files/                 <- from dist-update/files/ (not in git, not in the production image: mount it)
   ├─ Dofus Retro.exe
   └─ resources/app/retroclient/...
```

`public/launcher/files/.htaccess` turns off script execution for the payload. On nginx, do the
equivalent: inside `location /dofus/launcher/files/`, do not pass anything to PHP-FPM.

The launcher's `registerUrl` still points at `http://127.0.0.1/dofus/?page=register`; it is
redirected (301) to `/dofus/register`, but can be updated in `launcher.config.json`.
