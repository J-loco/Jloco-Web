# Phase 0 — Security fixes (no restructuring)

**Status: done (2026-09-13).** Verified end to end over HTTP with a throwaway account: register,
login (wrong password, throttle, remember-me cookie + rotation), CSRF rejection, logout with and
without token, profile toggles, secret-answer throttle, vote cooldown, purchase with too few
points and a successful purchase (points debited once, gift written, purchase logged), admin news
add/list/delete, drop search, job ladder. All PHP files lint; every page renders with no PHP notice.

Scope: close the holes from [audit.md](audit.md) inside the existing file layout. Every change
is compatible with Phase 2 (for instance, all links go through `url()` so switching to real
paths later is a one-function change).

## Tasks

- [x] **Router whitelist** (S1, D12) — `include/routes.php` lists every page and whether it shows
      the sidebar; `index.php` only includes pages from that list.
- [x] **`url()` helper** — every internal link is generated by `url('ladder', [...])`.
      Today it returns `?page=ladder`; Phase 2 makes it return `/ladder`.
- [x] **Escaping helper `e()`** (S5) — applied to every user- or DB-controlled value printed in
      HTML. Admin-authored news *content* stays raw HTML on purpose (trusted author).
- [x] **CSRF** (S3) — one session token; `csrf_field()` in every form; `index.php` rejects any POST
      without a valid token. State-changing GET links (logout, news deletion, vote) now require
      the token or were turned into POST forms. Exception: the Dedipass widget form (built by
      Dedipass JS), which is verified server-side against the Dedipass API instead.
- [x] **Session hardening** (S7) — `session.use_strict_mode`, `HttpOnly`, `SameSite=Lax`,
      `Secure` when served over HTTPS, `session_regenerate_id(true)` on login and logout.
- [x] **Remember-me tokens** (S6) — random selector/validator stored hashed in
      `website_remember_tokens`; rotated on use, deleted on logout.
- [x] **Brute-force throttle** (S8) — `website_auth_attempts`; 5 failures per 15 min per
      (IP, action) for login, password reset and secret-answer checks.
- [x] **Parameterized SQL everywhere** (S2) — no value is concatenated into SQL any more.
- [x] **Atomic shop purchase** (S9, D3) — `UPDATE ... SET points = points - ? WHERE guid = ? AND points >= ?`,
      checked via `rowCount()`, refunded if the gift write fails; purchase log uses the real table.
- [x] **Atomic vote + trusted proxy config** (S10) — `TRUST_CLOUDFLARE` env (default off).
- [x] **Protect internal folders** (S11, S18) — `Require all denied` in `configuration/`, `class/`,
      `include/`, `pages/`, `docs/`; root `.htaccess` returns 404 for `.git` and 403 for dotfiles,
      `*.md`, `Dockerfile`, and the disabled captcha.
- [x] **No DB error leak** (S12) — errors go to the PHP log; visitors see a generic message
      unless `APP_DEBUG=1`.
- [x] **Secrets out of `docker-compose.yml`** (S13) — `JLoco-Game/.env` (git-ignored) +
      `.env.example`. A dedicated least-privilege DB user is Phase 1.
- [x] **Password reset** (S14) — `random_int`, exact match, account kept in session between steps.
- [x] **Dedipass over HTTPS, key from env** (S15).
- [x] **Security headers** (S16) — `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`.
- [x] **Schema fixes touched along the way** — D3, D4, D5, D6, D11, D13 (shop lists the servers
      its items belong to), D14 (admin news inserts), D15 (forum news page).
- [x] **Launcher JSON** (D16) — `display_errors` now follows `APP_DEBUG` for every entry point and
      `utf8_encode` is gone, so PHP notices can no longer corrupt `launcher/news.php`.

Deferred to Phase 1: captcha (S17, needs GD in the image).

Known limitation, by design until Phase 2: page actions run after `include/header.php`, so a
flash message queued *before* a POST that redirects can be lost. Controllers fix this.

## New configuration (env of `jloco_web`)

Set in `JLoco-Game/.env` as `WEB_APP_URL`, `WEB_APP_DEBUG`, `WEB_TRUST_CLOUDFLARE`,
`WEB_DEDIPASS_PUBLIC_KEY` (mapped by `docker-compose.yml`); `DB_ROOT_PASSWORD` feeds both MariaDB and `DB_PASS`.

| Variable | Default | Meaning |
|---|---|---|
| `APP_URL` | `http://127.0.0.1/dofus/` | Public base URL, trailing slash |
| `APP_DEBUG` | `0` | Show PHP/DB errors to visitors |
| `TRUST_CLOUDFLARE` | `0` | Read the client IP from `CF-Connecting-IP` |
| `DEDIPASS_PUBLIC_KEY` | *(empty: reload tab hidden)* | Dedipass widget key |
| `DB_HOST`, `DB_PASS`, `LOGIN_HOST`, `GAME_HOST` | — | Already existed |

## Rules for new code (until Phase 2 replaces them)

- Never concatenate a value into SQL; use `?` placeholders.
- Wrap every printed value in `e()`.
- Every `<form method="post">` contains `<?= csrf_field() ?>`.
- Build internal links with `url()`, never with a literal `?page=`.
